# Project context for Claude Code

Custom HTML/CSS/JS blocks embedded in a Weblium-hosted site (https://sitwell.com.ua).
Weblium is a closed no-code builder; we can only inject code through its
"Embed code" blocks, so this repo produces standalone snippets, not a
deployed app. There is no bundler, no framework, no runtime dependencies.

## Repo layout

```
blocks/<name>/
  src/                   # edit these
    template.html        # HTML shell with {{STYLES}}, {{CONFIG_JSON}}, {{SCRIPT}}
    styles.css
    script.js
  config.json            # non-secret block config (map style, order keys, defaults)
  dist/                  # GENERATED — do not edit by hand (git-ignored)
  README.md
scripts/build.js         # zero-dep Node build (fs + string replace)
dev-server/              # local sandbox loading src/ directly
workers/<name>/          # Cloudflare Workers (order backend); wrangler + secrets
.githooks/pre-commit     # secret-scan guard; enable via `git config core.hooksPath .githooks`
.env                     # git-ignored; holds MAPBOX_TOKEN
```

## Golden rules

1. **Never edit `blocks/*/dist/index.html` by hand.** It is regenerated by
   `npm run build` from `src/*` + `config.json` + `.env`. Any manual edits
   are lost on the next build. If a change is needed in dist, change the
   source and rebuild.

2. **The Mapbox token is never hard-coded in `src/`.** The script reads it
   from `window.SLIPMAT_CONFIG.MAPBOX_TOKEN`, which is injected by
   `build.js` in production and by `dev-server/local-config.js` in dev.
   If you find yourself pasting `pk.ey...` into a `.js` file, stop.

3. **Never commit `.env`, `dev-server/local-config.js`, or
   `workers/*/.dev.vars`.** All contain live tokens. They are in `.gitignore`;
   keep it that way. Worker secrets go through `wrangler secret put`, never
   into tracked files.

4. **`dist/` is git-ignored** because the built files embed the token.
   To ship a build, regenerate locally with `npm run build` and paste the
   three `dist/weblium.*` files into the block's Custom Code tabs (see
   "Weblium constraints" — `index.html` is a reference only, never pasted).

5. **Enable the secret-scan hook once per clone:**
   `git config core.hooksPath .githooks`. It blocks any commit whose staged
   diff introduces a Mapbox / Resend / Telegram token or a private key.
   (We hit GitHub push-protection once already — this prevents a repeat.)

## Common tasks

**Local development**
```bash
npm run dev
# open http://localhost:5173/dev-server/
```
Edits to `blocks/<name>/src/*` show up on refresh — no build needed.

**Build for Weblium**
```bash
npm run build              # all blocks
npm run build:slipmat      # just slipmat-generator
npm run build:order        # just slipmat-order
```
Then paste the three generated files into the block's Weblium **Custom Code**
tabs: `dist/weblium.html` → HTML, `dist/weblium.css` → CSS, `dist/weblium.js`
→ JS. Save → Publish. (`dist/index.html` is a single-file reference — never
pasted.) See "Weblium constraints" for why the split is required.

**Adding a new block**
1. `mkdir -p blocks/<name>/src`
2. Copy the shape of `blocks/slipmat-generator/`
3. Update the runtime-config contract in `script.js` if you add new keys
4. Update `scripts/build.js` if the new block needs custom injections
   (usually it doesn't — the same template placeholder mechanism works)

## Blocks

### slipmat-generator

Interactive Mapbox generator for round vinyl-slipmat prints, live on
https://sitwell.com.ua/slipmats#services.

**Output:** PDF 310×310 mm (includes bleed), circular map area, transparent
background outside the circle, 5 mm centered pin-hole (transparent) with a
hairline circle + 1 mm cross alignment marker for the printer. Map raster
is stitched from 4 Mapbox Static tiles (2560×2560 each) into a 5120×5120
composite, downscaled to 3661×3661 (≈300 DPI on 310 mm).

**Runtime dependencies (loaded via CDN, do not vendor):**
- mapbox-gl 3.5.x
- mapbox-gl-geocoder 5.0.x
- jsPDF 2.5.x (UMD build; exposes `window.jspdf.jsPDF`)

**Runtime config contract:**
```js
window.SLIPMAT_CONFIG = {
  MAPBOX_TOKEN: 'pk...',
  MAPBOX_STYLE_GL: 'mapbox://styles/sitwell/...',
  MAPBOX_STYLE_STATIC: 'sitwell/...',
  START_CENTER: [lng, lat],
  START_ZOOM: <number>
}
```
The script does a sanity-check on these at startup and refuses to run if
anything critical is missing.

**Print-geometry constants (in `src/script.js`):**
`TARGET_SIZE_MM = 310`, `HOLE_DIAMETER_MM = 5`, `DPI = 300`.
Anything downstream (canvas sizes, marker sizes) is derived from these.
Change these if the physical slipmat size changes.

**Tile stitching invariant:** Static-API tile requests are always made
with `bearing=0` and `pitch=0`. Non-zero bearing/pitch would produce a
visible seam at the stitch boundaries. The interactive map on screen may
still be rotated/tilted — this is intentional, only export is forced flat.

**Roadmap:** Stage 1 (PDF export with pin-hole and marker) is done. Stage 2
(order flow) lives in the separate `slipmat-order` block below — this demo
generator stays as-is.

### slipmat-order

Stage 2 order variant. Target page (not yet published):
https://sitwell.com.ua/slipmats-with-custom-map (a duplicate of /slipmats).
Reuses the Stage 1 geometry/tiles/PDF, but instead of `pdf.save()` it builds a
Blob and POSTs it to a Cloudflare Worker with the order fields — **the customer
never downloads the file**.

**UI (dark theme, red accents):** full-width 3:1 interactive map with an 8 px
centered dot; **"Назва міста" is a geocoder** that names the order and flies the
map (the customer then fine-tunes the framing — the PDF is the source of truth
for what prints); round live preview; form (city / name / phone / delivery /
qty), price `PRICE_UAH` × qty; Turnstile + honeypot; inline thank-you; progress
states. Submit runs in **DRY-RUN** (logs, no POST) when `ORDER_ENDPOINT` is empty.

**No Weblium native cart.** The Weblium Store cannot be driven from custom code
(no add-to-cart JS API, no checkout prefill). Ordering is direct-to-Worker and a
manager handles payment. Do not attempt native-cart integration.

**Extra runtime-config keys (non-secret, in `config.json`):**
`ORDER_ENDPOINT` (Worker URL), `TURNSTILE_SITE_KEY` (public site key), `PRICE_UAH`.

**Backend:** `workers/slipmat-order/` — Cloudflare Worker (ES module + wrangler).
Verifies Turnstile + honeypot, then notifies via **Telegram `sendDocument`** and
**Resend email**, both with the PDF attached (Workers can't SMTP; MailChannels'
free tier is gone). Secrets via `wrangler secret put`: `TURNSTILE_SECRET`,
`RESEND_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `NP_API_KEY`. Local
dev uses `.dev.vars` (git-ignored). Deploy + setup: `workers/slipmat-order/README.md`.

## Weblium constraints

- **3-tab Custom Code.** Weblium's Custom Code block has separate HTML / CSS / JS
  tabs and mangles inline `<style>`/`<script>` pasted into the HTML tab.
  `build.js` therefore emits `dist/weblium.html`, `dist/weblium.css`,
  `dist/weblium.js` (plus `dist/index.html` as a single-file reference). Paste
  each file into its matching tab, then Save → Publish.
- **CDN `<script src>` tags must stay in the HTML tab** so the browser loads the
  deps (mapbox-gl, mapbox-gl-geocoder, jsPDF, Turnstile).
- **The native Store is isolated** from custom code — see the slipmat-order note.

## Code style

- ES2018+ (`.finally()` is used; async/await is fine).
- IIFE at the top level of `script.js` — no globals leak beyond
  `window.SLIPMAT_CONFIG` (which is set from outside).
- Prefer `var` and function declarations over `let`/`const`/arrow functions
  for consistency with the existing code. This is not a hard rule — just
  don't mix them in the same block.
- Sections in `script.js` are separated by `// ==========` banner comments.
  Keep new sections in the same style.
- No frameworks, no jQuery, no polyfills. If you find yourself adding a
  dependency, pause and reconsider — the "one file to paste into Weblium"
  constraint is the whole point.

## Non-goals for this repo

- Not a full site framework. If a task needs SSR, routing, or a real
  backend, it belongs in the future React/Next.js rewrite (separate repo),
  not here.
- Not a component library. Blocks are self-contained. Cross-block sharing
  is fine via `blocks/shared/*` if it emerges, but don't invent it
  preemptively.
- Not a place for secrets in code. If a task tempts you to hard-code a
  token or endpoint URL, put it in `.env` or `config.json` instead.
